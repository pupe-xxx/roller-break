# ROLLER BREAK

タイヤを転がして、盤の上の的を全部倒すパズル。ブラウザで動く。TypeScript + Vite + Canvas。
[web-game-template](https://github.com/pupe-xxx/web-game-template) から作った。STRATA の「転師」のタイヤを、1人用のパズルに切り出したもの。

## 遊び方

- 転師（黄色の六角形）のまっすぐ先のマスをタップすると、その向きにタイヤが転がる。黄色い線が、タイヤの通る道と止まる所
- **軽いタイヤ**は、的を1つ倒して止まる
- **重いタイヤ**は、的と壁を合わせて3つまで壊しながら進み、3つ壊した所で止まる。的は1つで1つ、壁は1段で1つと数える（2段の壁は2つ分）。転師に当たっても止まる。軽いタイヤと重いタイヤは、持っている数が別々に決まっていて、下のボタンに書いてある。合わせた数が、撃てる数
- **壁**に当たると、軽いタイヤは1段削って止まる。濃い壁は1段、中に明るい六角形がある壁は2段
- ほかの**転師**に当たると止まり、当たった転師は1マス押されて動く（先が空いている時だけ）。動いた転師は、撃てる線が変わる
- **板**（水色）に当たると、矢印の向きへ 60° 曲がって進み続ける。当たるたびに、板の向きが逆に切り替わる
- **鉄の壁**（びょう付きの暗い壁）は、どのタイヤでも壊れず、タイヤはそこで止まる
- **爆弾の的**（黒い玉付き）が倒れると、周りの6マスの的を倒し、壁を1段削る。巻き込んだ爆弾も続けて爆ぜる
- **盾付きの的**（水色の枠）は、軽いタイヤでは倒れず、そこで止まる。重いタイヤか爆弾で倒れる
- **ワープ穴**（同じ番号で2つ1組）に入ると、もう片方から同じ向きで出る
- **跳ね返す板**（銀色・Uの字の矢印）では、来た向きへ戻る。撃った転師に戻れば、その転師が押される
- 鉄の壁・ワープ穴・跳ね返す板へは、転師を押し込めない
- 転師が複数いる時は、転師をタップして撃つ転師を選ぶ
- 同じステージで2回失敗するたびに、ヒント（次の1手を見せる）が1回分増える。ボタンに、あと何回使えるかが出る
- 的を全部倒すとクリア。発射数が最少なら ★3、1発多いと ★2、それより多いと ★1。撃てるのは最少より3発多くまでで、それでも倒しきれないと失敗。タイヤが残っていても、どう撃っても盤が変わらなくなったら、その場で失敗になる（画面側の `src/ui/game.ts` が判定する）

ステージは100個。次のステージは遊び方を覚えるためのもの（手作り）。間のステージで、覚えたことを練習する。

| ステージ | 覚えること |
|---|---|
| 1 | 軽いタイヤ |
| 3 | 壁 |
| 5 | 重いタイヤ |
| 11 | 転師を押す |
| 20 | 板 |
| 41 | 板で曲げて押す |
| 51 | 鉄の壁 |
| 61 | 爆弾の的 |
| 71 | 盾付きの的 |
| 81 | ワープ穴 |
| 91 | 跳ね返す板 |

42〜60 は、板で曲げて押さないと最少では解けないステージと、それを使わない難しいステージが半分ずつ混ざる。52 以降の各10個は、その区切りで覚えた要素が無いと最少では解けない（前に出た要素も混ざる）。間のステージで、覚えたことを練習する。押すのを覚える 11 より前は、転師に当たっても押されない（ステージの `push: false`）。

ステージは20個ずつ5つに分かれていて、集めた星の合計が ★40・★80・★120・★160 に届くと、次の20個が開く（平均 ★2 で届く）。区切りの中では、クリアした一番先のステージの、2つ先まで遊べる。

## コマンド

| コマンド | すること |
|---|---|
| `npm run dev` | 手元で動かす |
| `npm test` | ルールの自動テスト。全ステージが解けることと、★3 の発射数が最少であることも確かめる |
| `npm run verify` | ★3 の発射数が最少であることを、別に書いた総当たりで確かめ直す |
| `npm run gen` | ステージを作り直す（`src/game/levels.gen.ts` を書き出す）。段階を2ステージずつの仕事に分けて、別々のスレッドで作る。数十分かかる。`npm run gen -- 7 8 9` のように段階の番号を渡すと、その段階だけ作り直す |
| `npm run record` | 動作記録（`tests/golden/golden.json`）を取り直す |
| `npm run typecheck` | 型の検査（ルール側が画面に触れていないかも見る） |
| `npm run build` | 検査してから `dist/` に公開用のファイルを作る |

## ステージの作り方

`scripts/gen.ts` が、乱数で盤を作り、総当たりで解いて、次の条件を満たすものだけ残す。乱数の種は固定なので、何度実行しても同じステージができる。

- 解ける。最少の発射数が、その段階の範囲に入っている
- **壁と板は、どれかの的のまっすぐ先のマスにだけ置く**（ほかの場所に置くと、タイヤが通らないので飾りになる。転師は押されて動くので、今の転師と的の間だけには絞らない）
- **最初から狙える的は3つに1つまで**（残りは壁かほかの的の後ろにある）
- **最初の1発の選び方が少ないステージは外す**（序盤の段階は `minChoices`。転師も最初から2人にする。撃てる所が1つしか無いと、迷わずに解けてしまう）
- **当たるものをでたらめに撃つと失敗する**：「盤が変わる発射」から毎回でたらめに選んで撃った時に、★2 が取れる発射数（最少＋1発）までに倒しきれる割合を計算し、段階ごとの上限（最初の段階は 30%、後ろの段階は 3%）より高いステージは外す。崩す壁・重いタイヤの使い所・どの転師で撃つかを間違えると足りなくなるステージだけが残る
- 重いタイヤは、1つ減らすと最少では解けない数だけ持たせる（余る重いタイヤを置かない）
- 転師が複数いるなら、どの1人が居なくなっても最少では解けない（使い道の無い転師を置かない）
- **押す段階は、転師を押さないと最少では解けない。板の段階は、板が無いと最少では解けない。42 以降は、半分のステージが、板で曲げたタイヤで転師を押さないと最少では解けない**（無くても同じ数で解けるなら、飾りになる）

段階（盤の広さ・的と壁と板の数・最少の発射数）は `scripts/gen.ts` の `TIERS` にある。段階の間に手作りのステージを挟む並びは `src/game/levels.ts` が決める。段階の数を変えたら、そちらも直す。変えたら `npm run gen` → `npm run record`。ステージの並びが変わったら、`src/ui/game.ts` の `saveKey` の番号を上げる（前の星が別のステージに付くため）。

## 最少の発射数の求め方

`src/game/solve.ts` が、1発目の撃ち方を全部、そのそれぞれに続く2発目を全部…と、発射数の少ない順に全部の撃ち方を調べる（幅優先）。最初に的が無くなった時の発射数が最少になる。速くするために「同じ盤面は1回だけ調べる」「盤が変わらない発射は飛ばす」の2つの近道をしている。

`npm test` は、全ステージで「★3 の発射数で解ける」「それより少ない発射数では解けない」を、この方法で確かめる。`npm run verify` は、別に書いた総当たり（1つの撃ち方を最後まで追ってから戻る順番で、盤が変わらない発射も飛ばさない）で同じことを確かめ直す。

## 守ること

型の README と同じ。特に次の2つ。

- **`src/game` は画面に触れない。** `Math.random` も時計も使わない
- **ルールやステージを意図して変えたら、動作記録を取り直す（`npm run record`）。**

## 公開

`main` に push すると、テスト → ビルド → GitHub Pages への公開まで自動で進む。
ゲームサイト（Poki・CrazyGames など）の広告 SDK は入っていない。差し込み口は `src/kit/platform/`。やり直しと次のステージの前に、区切りの広告を呼ぶ作りになっている。
